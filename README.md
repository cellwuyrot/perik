# Эфирия — архив RPG-мира, v2.2.0

Самодостаточный сайт на Node.js **22.9+** (рекомендуется актуальный Node 24), vanilla JS/CSS. Установка npm-зависимостей для работы сайта не нужна.

## Быстрый локальный запуск

```bash
npm start
```

Откройте `http://localhost:3000`. В архив уже включена демонстрационная база. **Не запускайте seed поверх своих данных.**

Первый локальный вход администратора: `http://localhost:3000/enter`, ник `admin@example.com`, пароль `change-me-now`. Это исключительно локальные демонстрационные значения. После авторизации кнопка «Админ» и пункт «Мастерская» возвращают в редактор, без повторного ввода пароля. Сессия хранится семь дней, переживает перезагрузку страницы и сервера, прекращается при выходе, отключении пользователя или сбросе пароля.

Для своей конфигурации скопируйте `.env.example` в `.env` и задайте ник/пароль/секрет **до первого запуска**. `npm start` автоматически читает `.env`. Изменение ADMIN_PASSWORD не меняет уже созданный аккаунт: используйте «Мастерская → Пользователи → Заменить пароль».

## Исправления

- Лор, Народы, Религии, События, Ветки сюжета, Юниты, Квесты, Сессии всегда доступны в меню, включая пустые разделы; создавать/редактировать записи можно в мастерской.
- Персонажи — каталог личностей мира и NPC. Листы персонажей — отдельный тип `sheets`, игровые данные с владельцем, характеристиками и инвентарём. Регистрация создаёт лист, а не дубликат в каталоге.
- При первом запуске старые `characters` с владельцем или видимостью PLAYER автоматически переносятся в `sheets`. Сохраняются ID, slug, содержимое, поля и связи. Создаётся `data/db.json.v2.1-backup` перед миграцией. Для ссылок на прежние листы работает перенаправление из `/entity/characters/...` в новый адрес.
- Юниты и Бестиарий имеют общую с Персонажами боевую форму и панель характеристик, включая золото и опыт. Сохраняются специфические поля монстров/юнитов.
- Предметы: КД (класс доспеха), Урон, Свойства. Старый ключ `ability` сохранён, поэтому данные не теряются.
- Редактор: заголовки, шрифт, размер, жирный/курсив/подчёркивание/зачёркивание, цвета, выравнивание, списки, отступы, ссылки, таблицы, изображения, отмена/повтор, очистка форматирования, счётчик слов. Сохраняет выделение при нажатии кнопок. Вставленный HTML очищается. Это встроенный веб-редактор, не Microsoft Word; DOCX-импорт/экспорт не реализован.
- Данные перечитываются при входе/выходе. Закрытые записи не остаются в интерфейсе после выхода; права проверяются на сервере по актуальному аккаунту.
- Исправлены секреты мастера в публичном API, скрытые маркеры/связи и конкурентные записи. PRIVATE доступен только ADMIN.

## Обновление существующего сайта

1. Остановите старый процесс. Скопируйте проект и сделайте отдельную резервную копию `data/` (включая uploads) и `.env`.
2. Замените код новой версией, но **сохраните свою папку `data/` и `.env`**, не заменяйте их демонстрационными.
3. Запустите `npm start`. Миграция выполнится один раз. Старые сессии версии 2.1 потребуют повторного входа — затем новые сессии сохраняются.
4. Проверьте мастерскую и игровые листы. Если ваши старые игровые персонажи были PUBLIC и не имели владельца, автоматическая миграция не угадывает их назначение. Смените тип записи на «Листы персонажей», назначьте владельца по нику и видимость PLAYER.

Владелец PLAYER назначается по нику пользователя (поле «Ник владельца») либо через API `ownerId`. У листа без владельца нет доступа у обычного игрока. Администратор/мастер/редактор видят доступные им листы. «Секреты мастера» доступны только редакционным ролям — не помещайте секреты в публичное описание.

## Проверки

```bash
npm run check
```

API-регрессии запускаются на временной базе и не затрагивают вашу базу. Для браузерных тестов нужны Playwright и Chromium (не нужны самому сайту):

```bash
npm install --no-save playwright
# CHROMIUM_PATH — путь к уже установленному браузеру
CHROMIUM_PATH=/usr/bin/chromium npm run test:ui
```

Результаты выполненных проверок: `docs/TEST_REPORT.md`. Исходный аудит: `docs/AUDIT_BEFORE.md`. Браузерные тесты сохраняют скриншоты в `test-results/`.

## Данные и безопасное развёртывание

База: `data/db.json`; файлы: `data/uploads`. Путь можно менять через DB_FILE/UPLOAD_DIR. Запись атомарна; API-запросы сериализованы в **одном процессе**. Не запускайте несколько экземпляров с одним JSON-файлом.

`npm run seed` создаёт демо только при отсутствии файла базы. Для намеренного сброса (уничтожает базу, аккаунты и историю): `npm run seed -- --force`.

Публичное размещение требует HTTPS, уникального SESSION_SECRET (32+ символа), собственного ADMIN_PASSWORD. Инструкция — `docs/PRODUCTION.md`. PostgreSQL-файл в `db/` — проект схемы для будущего переноса, **не подключённый runtime**.
