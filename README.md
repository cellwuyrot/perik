# Ashan Arcanum — архив Асхана, v2.3.0

Самодостаточный сайт на Node.js **22.9+** (рекомендуется Node 24), vanilla JS/CSS. Для запуска npm-зависимости не нужны. База — JSON, не PostgreSQL.

## Локальный запуск

```bash
npm start
```

Откройте `http://localhost:3000`. Демонстрационная база включена. **Не запускайте seed поверх своих данных.**

Первый локальный вход администратора: `http://localhost:3000/enter`, ник `admin@example.com`, пароль `change-me-now`. Это только демонстрационные значения. Для публичного сайта до первого запуска скопируйте `.env.example` в `.env`, задайте уникальный SESSION_SECRET от 32 символов, собственный ADMIN_PASSWORD от 12 символов и настройте HTTPS. Подробности: `docs/PRODUCTION.md`.

После создания аккаунта изменение ADMIN_PASSWORD в `.env` не меняет пароль: используйте «Мастерская → Пользователи → Заменить пароль».

## Что изменено

- AEtheria → **Ashan Arcanum**, Эфирия → **Асхан**.
- Итоговые названия из последних правок: «Обзор» → **Витрина**, «Мир» → **Каталог**, «Сеть мира» → **Паутина Асхи**.
- «Карта», «Карты», «Ветки сюжета» убраны из пользовательского интерфейса и мастерской. Их прежние данные не удаляются. Поиск убран только из левого меню; кнопка в верхней панели и поиск внутри разделов сохранены.
- Добавлена **Магия**: создание, редактирование, публикация, изображения и связи. Поля: школа, уровень, стоимость, время применения, дальность, длительность.
- У персонажей, юнитов и бестиария нет полей «Способности», «Категория». Ранг персонажа перенесён в «Титул»; у юнитов и бестиария ранга/титула нет. Старые скрытые значения сохранены для восстановления.
- У всех трёх типов есть **Урон**, выведенный над описанием вместе с HP, КД, золотом, опытом и прочими общими сведениями; «Титул» — только у персонажей. Повторы этих полей в боковой колонке убраны.
- Характеристики на странице: **С, Л, Т, И, М, Х**, без JSON и англоязычных сокращений. В форме: **Сила, Ловкость, Телосложение, Интеллект, Мудрость, Харизма**. Внутренние ключи STR/DEX/CON/INT/WIS/CHA сохранены для совместимости.
- Предметы: редкость, вес, **стоимость**, КД, урон — сверху; свойства и происхождение — в сведениях.
- Фракции: «Цель» → **Статус**; добавлено поле «Отношения» и отдельная вкладка на публичной странице. Внутренний ключ goal сохранён.
- Удалены старое приветствие и текстовые блоки главной рамки. Новые тексты заполняются через админку.
- Убраны белая подложка и стандартный чёрный цвет из вставленных документов; редактор соответствует тёмной теме. Явно заданные цветовые акценты сохранены.

## Настройка витрины и витражей

1. Войдите как ADMIN и откройте **Мастерская → Витрина и витражи** (`/admin/site`). GM, EDITOR и PLAYER не могут менять глобальную витрину.
2. Заполните надзаголовок, заголовок/текст приветствия, заголовок/текст вводного раздела. Пустые поля не отображаются. Вводный текст поддерживает Markdown и безопасный HTML, приветствие — обычный текст.
3. Нажмите **Добавить витраж**, загрузите PNG/JPEG/WEBP/GIF до 5 МБ или укажите HTTPS/локальный URL. Заполните заголовок и текст карточки. Можно добавлять до 60 карточек, заменять изображения, редактировать, удалять и менять порядок кнопками «Выше/Ниже».
4. Укажите дату начала цикла и часовой пояс (по умолчанию **Europe/Moscow**). Нажмите **Сохранить витрину**: загрузка файла сама по себе ещё не публикует карточку.
5. Карточка меняется **раз в календарный день в полночь выбранного часового пояса**, по общему порядку для всех посетителей. После последней повторяется первая. До даты начала показывается первая карточка. Открытая вкладка проверяет смену дня каждые 30 секунд.
6. Если карточки есть, их заголовок и текст заменяют общее приветствие. Если карточек нет, отображается общее приветствие. Если всё пусто, остаётся декоративная рамка с кнопками перехода.

Это ежедневная ротация, не слайдер с секундным интервалом. Настройки и карточки сохраняются в `data/db.json`, изображения — в `data/uploads`. Их необходимо резервировать вместе. Все тексты витрины публичны: не добавляйте туда секреты мастера.

## Обновление существующего сайта

1. Остановите старый процесс. Сделайте независимую резервную копию `data/` (включая uploads) и `.env`.
2. Замените код новой версией, **сохранив свою папку `data/` и `.env`**. Не заменяйте их демонстрационной базой из архива.
3. Запустите `npm start`. Перед миграцией базы предыдущей версии создаётся `data/db.json.pre-2.3-backup`. Миграция добавляет настройки витрины и переносит rank персонажей в title, не удаляя старые поля. Прежние персонажи с владельцем/PLAYER в базе до версии схемы 2 становятся игровыми листами `sheets` с сохранением ID и связей.
4. Проверьте каталог, листы персонажей и мастерскую. Старые игровые персонажи PUBLIC без владельца автоматически не переклассифицируются: задайте тип «Листы персонажей», владельца по нику и видимость PLAYER вручную.

Технические идентификаторы cookie `aetheria_session` и Docker volume `aetheria-data` оставлены для совместимости со старыми сессиями/данными. Это не пользовательский бренд. Если переносите проект в другую директорию и используете Docker Compose, сохраните прежний compose project name (`docker compose -p ПРЕЖНЕЕ_ИМЯ …`) либо явно перенесите том: иначе Compose создаст новый том.

## Тесты

```bash
npm run check
```

Тесты работают на временных базах, не затрагивают вашу базу. Для браузерных тестов нужны Playwright и Chromium (самому сайту не нужны):

```bash
npm install --no-save playwright
CHROMIUM_PATH=/usr/bin/chromium npm run test:ui
```

Отчёт: `docs/TEST_REPORT.md`. Логи и скриншоты: `test-results/`. Проверялась локальная сборка; развёртывание на вашем сервере и HTTPS зависят от вашего окружения.

## Хранение данных

Один процесс Node.js: операции API сериализованы, запись JSON атомарна. **Не запускайте несколько экземпляров с одним JSON-файлом.** Пути можно менять переменными DB_FILE/UPLOAD_DIR. `npm run seed` создаёт демо только при отсутствии базы; `npm run seed -- --force` уничтожает текущие данные.

`db/schema.sql` — заготовка PostgreSQL-схемы, не используемый runtime. Документы релиза 2.2 и исходный аудит сохранены как исторические; актуальная инструкция — этот README.
